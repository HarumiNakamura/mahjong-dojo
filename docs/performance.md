各ページ2〜3回計測した範囲。ホームは 90(TBT 330 ms)から 98 になった。

- **原因**:日本語の文字の配置(レイアウト)は1回でも重く(4倍遅い CPU で 1回 100〜400 ms)、ホームでは何度もページ全体の配置をやり直していた。「1問だけ何切る」の問題作りは約 100 ms で、主な原因ではなかった
  1. ホームは紹介だけの HTML を画面ができたら丸ごと置きかえていたので、すべての文字を2回配置していた → 本文まで HTML にして引き継ぐ(学習記録は最初は「記録なし」で表示し、画面ができてから入れかえる)
  2. 2秒後に読み込むフォントの CSS が、ファイルが届くたびにページ全体の配置をやり直させていた(3回で 300 ms 以上)。`font-display: optional` なので、はじめて開いたときはフォントが表示に使われないのに、配置のやり直しだけが起きていた → はじめては CSS を当てず、読み込み終わって3秒後の空いた時間にフォントのファイルだけを読み込んでおき、2回目から CSS を当てる(`src/app/fonts.ts`)

- Web フォント(BIZ UDPゴシック・しっぽり明朝 B1)をそのまま読み込むと、`@font-face` の CSS だけで約180KB になり、ホームの速さが 56 まで下がった
- 対応: サイトで使う文字だけの `@font-face` を作り(`scripts/build-font-css.mjs`、約1,150文字・CSS 約60KB)、ページの読み込みが終わって2秒後に読み込む。`font-display: optional` なので、はじめて開いたときは端末のフォント、2回目からはサイトのフォントで表示する(文字の入れ替えで表示がずれない)
- ホームの「1問だけ何切る」の問題作りは、最初の表示のあとに行う
- ホームの TBT が残っているのは、牌の絵(SVG)が多いため

手元のプレビュー(`npm run build` → `vite preview`)を Lighthouse 12 のモバイル設定(通信と CPU を遅くした状態)で計測しました。
本番(Cloudflare)は圧縮して配信するので、通信の時間はこれより短くなる見込みです。

## 行った改善

| 改善前の問題 | 対応 |
| --- | --- |
| JS が1つにまとまっていて大きい(500 kB 超の警告) | ページごとに分けて、必要になったときに読み込む(最初の JS は約 280 kB・圧縮後 約 93 kB。記事の本文 約 110 kB は解説を開いたときだけ) |
| 記事ページで表示がずれる(CLS 0.86) | ビルド時に本文まで入った HTML を作り、そのまま引き継ぐ(読み込み中の表示と差し替えない) |
| ドリルのページで、読み込み後に広告枠とフッターが下にずれる(CLS 0.44) | 読み込み中の表示に画面の高さを取っておく |
| ホームで「今日の練習」の5問を作るのに時間がかかる(TBT 570 ms) | 5問は「今日の練習」ページで作り、ホームは保存したキーで解いた数を数える |
| 弱点マップの薄い文字のコントラスト不足 | 透明度ではなく、決まった薄い文字色を使う |

## 検索対策

- ページごとに題名・説明・canonical・OGP(og:title・og:description・og:image など)・X カード(summary_large_image)を、ビルド時の HTML に入れる(`src/app/seo.ts`、`scripts/prerender.mjs`)
- 記事・一覧など内容が毎回同じページは、本文まで HTML にする(JavaScript がなくても読める)
- `sitemap.xml`・`robots.txt` をビルド時に作る。共有・解き直し・開発用・見つからないページは `noindex`
- どのページを直接開いても、再読み込みしても 404 にならない(`dist/<パス>.html` を作る)。存在しないパスは `404.html` を 404 の状態で返す
